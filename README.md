# Рацион — расчёт энергозатрат и подбор рациона

Flutter-приложение (Windows → Android/iOS), объединяющее логику
«Калькулятор .xlsx» и «Конструктор рациона.xlsx».

## Подготовка окружения (Windows)

1. **Git for Windows** — https://git-scm.com (нужен Flutter).
2. **Flutter SDK** — https://docs.flutter.dev/get-started/install/windows
   (распаковать, например, в `C:\dev\flutter`, добавить `C:\dev\flutter\bin` в PATH).
3. **Visual Studio 2022 Community** с нагрузкой «Разработка классических приложений на C++» —
   нужна для сборки под Windows.
4. **Android Studio** — Android SDK и эмулятор (для Android-версии).
5. **Режим разработчика Windows** (Параметры → Конфиденциальность и защита → Для разработчиков) —
   Flutter-плагинам нужны символические ссылки.
6. **VS Code** + расширение *Flutter*.

Проверка: `flutter doctor` — все пункты для Windows должны быть зелёными.

## Первый запуск

В репозитории только исходники; платформенные папки (`windows/`, `android/`, `ios/`)
генерирует Flutter — существующие файлы при этом не перезаписываются:

```
cd ration_planner
flutter create . --platforms=windows,android,ios --project-name ration_planner
flutter pub get
flutter test
flutter run -d windows
```

## Логика расчёта

| Показатель | Формула |
|---|---|
| ккал/мин | MET × 3,5 × масса / 200 |
| BMR | 10·масса + 6,25·рост − 5·возраст **+ 5** (м) / − 161 (ж) |
| TDC без тренировки | BMR × 1,2 |
| Ккал тренировки | ккал/мин × минуты **или** значение с фитнес-браслета (ручной ввод) |
| TDC с тренировкой | BMR × 1,2 + ккал тренировки |
| Цель на день, ккал | выбранный TDC × (1 + дефицит/профицит % / 100) |
| Белки, г | 0,6–2,0 г × масса тела |
| Жиры, г | 10–30 % цели / 9 |
| Углеводы, г | (цель − белки × 4 − жиры × 9) / 4 |

Исправлено относительно Excel: в мужском BMR было «−5» вместо «+5»; мужской
«TDC с тренировкой» ссылался на пустую ячейку минут.

**Ввод.** Шаг 1: пол, масса, рост, возраст. Шаг 2: выбор расчёта — «Рацион питания» или
«Процент подкожного жира». Шаг 3 (рацион): способ расчёта BMR, тренировка (вид нагрузки
из справочника + длительность, или калории с браслета), дефицит/профицит, БЖУ (ползунки).

**Процент подкожного жира** (калиперометрия, `lib/domain/body_composition.dart`;
эталоны — «Процент подкожного жира у мужчин/женщин.xlsx»):

| Показатель | Формула |
|---|---|
| Складки | мужчины — 8 точек, женщины — 7 (без груди), мм |
| Площадь тела (Мостеллер) | √(рост, см × масса, кг / 3600) |
| Средняя полутолщина складки | сумма складок / (2 × число точек) |
| Масса жира (Матейка) | полутолщина × площадь тела × 1,3 |
| % жира / LBM | жир / масса × 100; масса − жир |
| Мышечная масса (Ли, вариант Excel) | рост, м × (0,00088·(обх. бедра − скл. бедра/10)² + 0,00744·(обх. плеча − скл. плеча сзади/10)² + 0,00441·(обх. голени − скл. голени/10)²) + 2,4·пол − 0,048·возраст + 7,8 |
| Коэффициент по % жира (лист «схема») | муж: < 14 → 1; 14–20 → 0,95; 20–28 → 0,9; > 28 → 0,85. Жен: < 18 → 1; 18–28 → 0,95; 28–38 → 0,9; > 38 → 0,85 |
| BMR по % жира | масса × 24 × (1 муж / 0,9 жен) × коэффициент |

В оригинале уравнения Ли из обхвата вычитается π × складка (см); здесь, как в исходном Excel, — без π.
Результат калиперометрии можно перенести в рацион: BMR будет считаться по % жира.

**Рацион.** Итог за день совпадает с целью по ккал, белкам и жирам (углеводы — остаток).

1. Калории цели делятся между строками по долям шаблона (ккал строки в исходном
   «Конструкторе»: гречка 330 из 2152,4 ккал и т.д.).
2. Порции каждой группы продуктов — белковые / жиры / углеводные (злаки, перекусы) —
   умножаются на свой коэффициент; три коэффициента — решение системы
   «ккал = цель, белки = цель, жиры = цель». Если неотрицательного решения нет
   (например, в рационе нет ни одного жира), порции подбираются только по калориям,
   а на экране показывается предупреждение.
3. Округление до 1 г; погрешность по калориям компенсируется в строке с наименее
   калорийным продуктом.

- число приёмов (`lib/domain/meal_layout.dart`) — основные 1–3 (3: завтрак, обед, ужин;
  2: завтрак и ужин; 1: ужин) и перекусы 1–3; чередуются. Пустые и недостающие перекусы — копия
  первого. Приёмы, которые остаются, сохраняют выбранные продукты; выбор запоминается;
- замена продукта — доля строки сохраняется, порции пересчитываются;
- продукт в пустом месте — входит с базовой порцией места, доли остальных строк уменьшаются;
- ручная порция — фиксируется (отмечена ✎), остальные строки подстраиваются под цель;
  кнопка «⚖» сбрасывает ручные правки.

## Структура

```
lib/
  domain/   models.dart, energy_calculator.dart, ration_plan.dart — чистая логика
  data/     database.dart (SQLite-схема), seed.dart (шаблон, переводы), repository.dart
  state/    providers.dart — Riverpod: справочники, профиль, текущий расчёт
  ui/       profile_screen.dart (шаг 1), choice_screen.dart (шаг 2 — выбор расчёта),
            training_screen.dart и body_fat_screen.dart (шаг 3), ration_screen.dart,
            activity_picker.dart, form_widgets.dart (общие поля, инструкция),
            theme.dart (цвета), app_logo.dart (логотип), theme_toggle.dart
assets/seed/  foods.json, activities.json — справочники из xlsx
              activities_ru.json — русские названия видов нагрузки (код → название)
assets/icon/  app_icon_256.png — исходник иконки
tools/        export_seed.ps1 — повторный импорт справочников из xlsx
              split_merged_activities.ps1 — разбор склеенной строки 19405 исходного Excel
              package_windows.ps1 — релизная сборка + zip в dist\
              make_ico.ps1 — сборка .ico из PNG
test/         unit-тесты формул и рациона (эталоны из Excel), widget-тест сценария
```

База — SQLite-файл `%APPDATA%\ration_planner\ration_planner.db`. Справочники
заливаются при первом запуске; чтобы перезалить после изменения `assets/seed`,
удалите файл БД.

## Готовая сборка под Windows

```
powershell -ExecutionPolicy Bypass -File tools\package_windows.ps1
```

Результат: папка `dist\Ration\` (exe + DLL + библиотеки Visual C++ + README.txt)
и архив `dist\Ration-<версия>-windows-x64.zip`. Версия берётся из `pubspec.yaml`.

## Готовая сборка под macOS

Собрать macOS-приложение можно только на Mac (требование Apple). Два способа:

1. **На своём Mac** (Xcode + Flutter): `bash tools/package_macos.sh` →
   `dist/Ration-<версия>-macos.dmg` (универсальная сборка Apple Silicon + Intel, macOS 12+).
2. **В облаке GitHub Actions** — `.github/workflows/build.yml`: тесты, затем сборки
   macOS (.dmg) и Windows (.zip) на серверах GitHub. Запуск — Actions → «Build releases» →
   Run workflow (или push тега `v*`); файлы — в Artifacts запуска.

Приложение не подписано сертификатом Apple Developer — при первом запуске macOS
предупредит о неизвестном разработчике (как открыть — в `tools/dist_readme_macos.txt`,
он кладётся в .dmg). Для подписи и нотаризации нужен Apple Developer Program.

Настройки macOS: имя и bundle id — `macos/Runner/Configs/AppInfo.xcconfig`,
отображаемое имя и регион — `macos/Runner/Info.plist`, размер окна —
`macos/Runner/MainFlutterWindow.swift`, иконки — `macos/Runner/Assets.xcassets/AppIcon.appiconset`.
